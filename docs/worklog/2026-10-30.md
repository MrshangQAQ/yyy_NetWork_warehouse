## 二、v2 设计：GPUBatchMatrix（用户方案）

核心思路（用户）：

- 一个类持有 **显存中的 `float*` + 4 个维度**（`OutRow, OutCol, InRow, InCol`），
  对应 `[R][C][H][W]` 的连续布局，与现有 `Batch_Matrix` 一致；
- **固定大小、常驻显存**：初始化时 CPU 生成（含 `Random` 等只能在 CPU 做的操作）→ 上传一次；
- 拷贝禁用、允许移动；提供与 CPU `Batch_Matrix` 的往返转换（`ToCPUBat` / 构造函数）；
- 外层仍由 CPU 控制，不引入"图执行器"，神经网络代码结构不大改；
- 逐元素、池化、反池化、Dilate 等**写成 GPU kernel 并行执行**（如反池化按 argmax 索引 scatter，天然无竞争）。

## 三、今天解决的构建/链接问题（本次最有价值的部分）

### 3.1 C1071「注释中遇到意外的文件结束」与「expected "}"」是同一个根因

用户最初遇到 C1071，随后通过在文件末尾加 `/**/` 让错误变成 `expected "}"`。排查结论：

- 文件字节本身是对的（hexdump 确认 L507 是 `...8F 2A 2F`，`2A 2F` 就是 `*/`）；
- MSVC 默认按 **GBK(936)** 读源码，而源文件是 UTF-8：中文的尾字节被当成 GBK 双字节首字节，
  **吞掉了后面的 `*`**，`*/` 变成 `/` → 注释没有闭合 → C1071；
- 末尾的 `/**/` 只是把注释在 EOF 处闭合，导致 **L507 到文件末尾的代码（包括函数的 `}`）全被注释掉** → `expected "}"`。

**正确修复**：让编译器按 UTF-8 解析源码。工程里加入：

```
ClCompile:    /source-charset:utf-8
CudaCompile:  -Xcompiler /source-charset:utf-8
```

使用 `source-charset` 而不是 `/utf-8`：执行字符集不变，中文 `cout` 输出不受影响。
同时满屏的 **C4819** 警告消失。

**教训**：看到 C4819 满屏，先修编码，不要逐个注释去猜。

### 3.2 LNK2005：头文件里不能定义可变全局变量

`Bat_Convolution_Gpu` 的 `pinner_in / pinner_out / d_inMat_f / ...` 原本放在 `Batch_Matrix.h` 里
**直接定义**，每个包含该头文件的 `.cpp/.cu` 都生成一份定义 → 链接期大量 `LNK2005`。

修复：头文件改为 `extern` 声明，定义放到 `Batch_Matrix_GPU_.cu`（全项目唯一一份）。
这正是 10-29 维护日志里「头文件不放可变全局状态」那条，今天以链接错误的形式应验。

### 3.3 C4716 与内存泄漏

- `operator-=` / `operator*=` / `ToCPUBat` 返回类型不是 `void` 却缺 `return` → C4716；
- `TryMatchWith` 重新分配前没有释放旧 `data_` → 泄漏；已改为先 `cudaFree` 再 `cudaMalloc`。
