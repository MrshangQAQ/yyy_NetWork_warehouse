## 二、实际产出

### 2.1 矩阵乘 A 路径（M1 的 P1 项）

```
主机 double
  → [AVX2 + OpenMP] double→float
  → 锁页缓冲（只增不减、跨版本复用、首次分配后 memset 预热）
  → cudaMemcpyAsync H2D（float，字节减半）
  → GEMM kernel（输出类型模板化，直接写 float）
  → cudaMemcpyAsync D2H → 锁页
  → [AVX2 + OpenMP] float→double 写回 out
```

- 传输路径**运行时开关**：`SetMatMulTransferMode(1)` A 路径 / `0` 旧 pageable 路径；
- 计时：`MATMUL_GPU_TIMING=1` 打印 pack / H2D / kernel / D2H / unpack；
- 数值对拍（与 CPU 结果比较）：5 个形状相对误差 **3.5e-7 ~ 1.8e-6**（FP32 正常范围）。

单次耗时（128×1024×2000，计时开启）：

| 阶段 | 数值 |
|---|---|
| pack | 0.8 ~ 1.1 ms |
| H2D | 0.9 ~ 1.3 ms |
| kernel | 0.3 ~ 0.6 ms |
| D2H + unpack | 0.05 ~ 0.9 ms |
| **合计** | **2.2 ~ 3.0 ms** |

### 2.2 修复一：`.cu` 主机代码的 OpenMP 一直是空转（AI 发现）

VS 的 CUDA 项目用 nvcc 编译 `.cu`，**主机编译选项和 C++ 项目的 `/openmp`、`/arch:AVX2` 是分开的**。
`imcol2_GPU.cu` 里所有 `#pragma omp parallel for` 之前全部被忽略（不报错，当注释处理）。

**证据**：A 路径转换加上 OpenMP 前后，同一形状同一条代码路径的 pack：**3.1 ms → 1.08 ms**。

**修复**：`高等代数.vcxproj` 的 CudaCompile 增加
```
-Xcompiler /openmp -Xcompiler /arch:AVX2
```

### 2.3 修复二：GPU 矩阵乘其实从未启用（AI 发现）

- `main.cpp` 里 `SetMatMulGpuThreshold(...)` 被注释掉；
- `Matrix_Double_Mutiple_GPU.cu` 里默认阈值又被改成 `1024*1024*1024`。

结果：**`NN_ACCEL=gpu` 和 `NN_ACCEL=conv` 跑的是同一条路径**——
之前所有"GPU 矩阵乘没收益"的 epoch 对比，其实根本没测到 GPU 矩阵乘。

修复后（阈值 2M + 形状判据），A 路径下 GPU 矩阵乘真正反超 CPU（见 2.4）。

### 2.4 修复三：新增微基准工具 Bench（用户："什么都测不出来" → AI 实现）

- `Bench.cpp` / `Bench.h`：matmul / conv 微基准；**同一进程内交替采样**（抗机器漂移），预热后报告 min / median / mean / GFLOP/s；
- 入口：`NN_BENCH=matmul|conv|all`；`NN_BENCH_SHAPE` / `NN_BENCH_MODES` / `NN_BENCH_ITERS` / `NN_BENCH_WARMUP` 可调；
- 脚本：`run_bench.cmd`（包装 `run_bench.ps1`，绕过执行策略），结果存 `docs/bench/`。

## 四、方法论：epoch 为什么测不出来（今天最重要的结论）

同一份程序、同样参数，今天前后两次测得：

| 模式 | 上午/上次 | 本次 |
|---|---|---|
| 全 CPU epoch | 12.9 s | **22 ~ 25 s** |
| conv-gpu epoch | 9.7 s | **15 ~ 16 s** |

机器状态（后台进程 / 温度 / 功耗策略）带来的漂移 **±60%**，而 M1 想量的边界优化只有 10~100 ms（约 1%）。

| 层级 | 测什么 | 噪声 | 用途 |
|---|---|---|---|
| L0 单算子 | 一次 matmul / conv 的分段耗时 | ±1~5% | 优化决策（用 Bench） |
| L2 epoch | 一个 epoch | ±5~60% | 只用于 ≥10% 的改动，且同会话跑对照取比值 |

**换问法**：从"变快了吗"变成"到上限了吗"——
pack 25 MB / 1.1 ms ≈ 23 GB/s（接近内存带宽，继续优化意义不大）；
matmul H2D 8.5 MB / 0.9 ms ≈ 9 GB/s（离 PCIe 上限还有空间）。

## 五、差点误判的一次（今日最大收获）

A 路径第一次实现时，pack 是 3.1 ms、与旧路径持平 → 差点得出「锁页 + 转换没用」的结论。
真正原因不是锁页，而是**转换是单线程的**（见 2.2）。补上 OpenMP 后 pack 1.08 ms，结论才成立。

**教训：一个优化"没效果"时，先确认它真的执行了（编译选项、路径开关、日志），再怀疑设计。**
